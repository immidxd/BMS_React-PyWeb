## Оновлення: Віджет прогресу парсингу (2025-08-18)

Це оновлення виправляє проблему з невідображенням прогрес-вікна після старту парсингу та стабілізує запуск бекенду під PyWebView.

### Що змінено

1) Frontend
- `frontend/src/layouts/MainLayout.tsx`
  - Запуск парсингу переведено на реальний ендпоїнт `/api/parsing/run?mode=...` з передачею `{ params }`.
  - `currentJobId` більше не скидається при закритті діалогу, щоб віджет прогресу не зникав.
  - Показуємо прогрес-вікно миттєво: виставляємо тимчасовий `jobId = -1`, щоб віджет з’являвся в стані «З’єднання…», допоки не прийде реальний `jobId` з API.
  - Fallback: якщо `/api/parsing/run` тимчасово недоступний, створюємо тестову job через `/api/parsing/test`, щоб віджет все одно показався (для діагностики).

- `frontend/src/App.tsx`
  - Аналогічні зміни запуску та миттєвого відображення прогресу (тимчасовий `jobId=-1`).

- `frontend/src/components/ParsingStatus.tsx`
  - Віджет відображається одразу при наявності `jobId` (навіть якщо ще не надійшов перший WS пакет).
  - Спрощено резервний поллінг без дубльованих інтервалів.

2) Backend
- `backend/app/main.py`
  - Логування переведено на абсолютний шлях `backend/app/app.log` з гарантованим створенням директорії. Це усуває збій запуску під PyWebView, коли CWD відрізняється.

### Важливі примітки (поточні обмеження)
- Віджет прогресу **відображається**, але працює «топорно»:
  - Парсинг як такий ще не перевірено в повному циклі.
  - Статуси можуть **не оновлюватися** в реальному часі, якщо бекенд не пушить heartbeat у `parsing_jobs` або WS не доставляє події.
  - Потрібно додатково перевірити, що `UnifiedParser` викликає `status_callback` і що `/api/parsing/jobs/{id}/stream` стабільно стрімить оновлення.

### Як відтворити/перевірити
1. Зібрати фронтенд:
```
cd frontend
npm run build
```
2. Запустити додаток з кореня:
```
source venv/bin/activate
python main.py
```
3. В UI натиснути «Оновити» → вибрати режим → «Почати парсинг».
4. Очікувано з’являється прогрес-вікно (спочатку «З’єднання…», потім відсотки/ETA).

### Наступні кроки
- Перевірити реальну доставку прогресу з `UnifiedParser`:
  - чи викликається `status_callback`;
  - чи оновлюється `parsing_jobs` (percent, processed_items, last_heartbeat_at);
  - чи стабільно працює WS `/api/parsing/jobs/{jobId}/stream`.
- Після підтвердження – прибрати тимчасові `alert()` та діагностичні логи, а також при потребі ввімкнути прогрес прямо у діалозі вибору режиму.
