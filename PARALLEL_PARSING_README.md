## 🎯 Що це таке?

**Паралельна обробка** - це нова функція системи парсингу BMS, яка дозволяє обробляти дані з Google Sheets **в 3-4 рази швидше** за рахунок одночасної обробки кількох аркушів або пакетів даних.

### Ключові можливості:
- ⚡ **Прискорення в 3-4 рази** порівняно зі звичайним парсингом
- 🔄 **Автоматичний розподіл** задач між воркерами
- 📊 **Відстеження прогресу** в реальному часі
- 🛡️ **Захист від помилок** з автоматичними повторними спробами

## 🎮 Як використовувати

### Варіант 1: Через інтерфейс програми (РЕКОМЕНДОВАНО)

1. **Відкрийте програму BMS**
2. **Натисніть кнопку** 🔄 **Парсинг**
3. **Виберіть один з паралельних режимів:**
   - ⚡ Паралельний повний парсинг
   - 📦⚡ Паралельний парсинг товарів
   - 🛒⚡ Паралельний парсинг замовлень
4. **Натисніть "Почати"**

### Варіант 2: Через командний рядок

```bash
# Паралельний повний парсинг
python backend/scripts/unified_parser.py --mode parallel_full

# Паралельний парсинг тільки товарів
python backend/scripts/unified_parser.py --mode parallel_products

# Паралельний парсинг тільки замовлень
python backend/scripts/unified_parser.py --mode parallel_orders

# Тестування паралельної обробки
python backend/scripts/test_parallel_parsing.py
```

## ⚙️ Налаштування

### Основні параметри (за замовчуванням оптимальні)

Файл: `backend/scripts/config.py`

```python
PARSING_CONFIG = {
    "parallel": {
        "enabled": True,        # Увімкнути/вимкнути паралельну обробку
        "max_workers": 8,       # Кількість паралельних потоків (рекомендовано: 4-8)
        "batch_size": 50,       # Розмір пакету даних (рекомендовано: 50-100)
        "db_pool_size": 10,     # Кількість з'єднань з БД (рекомендовано: 10)
    }
}
```

### Рекомендовані налаштування для різних систем:

| Тип системи | max_workers | batch_size | db_pool_size |
|-------------|-------------|------------|--------------|
| **Слабкий ПК** (2-4 ядра) | 2-4 | 25 | 5 |
| **Середній ПК** (4-8 ядер) | 4-6 | 50 | 10 |
| **Потужний ПК** (8+ ядер) | 6-8 | 100 | 15 |

### Як змінити налаштування:

1. Відкрийте файл `backend/scripts/config.py`
2. Знайдіть секцію `"parallel"`
3. Змініть потрібні параметри
4. Збережіть файл
5. Перезапустіть програму

## 📊 Режими роботи

### 🚀 Паралельний повний парсинг
- **Що робить:** Парсить ВСІ товари та замовлення паралельно
- **Коли використовувати:** Для повного оновлення бази даних
- **Час виконання:** 30-45 хвилин
- **Команда:** `--mode parallel_full`

### 📦 Паралельний парсинг товарів
- **Що робить:** Парсить ТІЛЬКИ товари з таблиці "Журнал"
- **Коли використовувати:** Коли потрібно оновити каталог товарів
- **Час виконання:** 15-25 хвилин
- **Команда:** `--mode parallel_products`

### 🛒 Паралельний парсинг замовлень
- **Що робить:** Парсить ТІЛЬКИ замовлення з таблиці "Замовлення"
- **Коли використовувати:** Коли потрібно оновити замовлення клієнтів
- **Час виконання:** 15-25 хвилин
- **Команда:** `--mode parallel_orders`

## 📈 Моніторинг прогресу

Під час паралельної обробки ви бачите:
- **Кількість задач:** загальна та виконана
- **Прогрес у відсотках**
- **Швидкість обробки:** задач/секунду
- **Оцінка часу:** скільки залишилось
- **Поточні задачі:** що обробляється зараз

Приклад виводу:
```
Паралельна обробка: 45/100 задач (45%)
Швидкість: 2.3 задачі/сек
Залишилось: ~24 секунди
Активних воркерів: 6/8
```

## ⚠️ Важливо знати

### Системні вимоги:
- **RAM:** мінімум 4 GB (рекомендовано 8 GB)
- **CPU:** мінімум 2 ядра (рекомендовано 4+)
- **Диск:** 500 MB вільного місця для кешу

### Обмеження:
- Google API ліміт: 100 запитів за 100 секунд (не змінюється)
- База даних: максимум 10-15 одночасних з'єднань
- Пам'ять: паралельна обробка споживає більше RAM

## 🔧 Вирішення проблем

### ❌ Проблема: "too many clients already"
**Причина:** PostgreSQL досяг ліміту з'єднань (зазвичай 100)

**ШВИДКЕ РІШЕННЯ:**
1. **Перезапустіть програму** (закрийте та відкрийте)
2. Запустіть скрипт діагностики:
   ```bash
   python backend/scripts/fix_db_connections.py
   ```

**ПОВНЕ РІШЕННЯ:**
1. Відкрийте файл PostgreSQL конфігурації:
   - macOS: `/usr/local/var/postgres/postgresql.conf`
   - Linux: `/etc/postgresql/*/main/postgresql.conf`
2. Знайдіть рядок `max_connections = 100`
3. Змініть на `max_connections = 200`
4. Перезапустіть PostgreSQL:
   ```bash
   brew services restart postgresql  # macOS
   sudo systemctl restart postgresql  # Linux
   ```

### Проблема: "Паралельний парсер недоступний"
**Рішення:** 
1. Перевірте наявність файлу `backend/scripts/parallel_parser.py`
2. Встановіть залежності: `pip install -r requirements.txt`

### Проблема: Програма зависає або працює повільно
**Рішення:**
1. Зменшіть `max_workers` до 2 в `config.py`
2. Зменшіть `batch_size` до 15
3. Перезапустіть програму

### Проблема: Помилки підключення до БД
**Рішення:**
1. Запустіть: `python backend/scripts/fix_db_connections.py`
2. Перевірте налаштування PostgreSQL
3. Збільшіть max_connections в PostgreSQL

### Проблема: Високе використання пам'яті
**Рішення:**
1. Зменшіть `batch_size` до 15
2. Зменшіть `max_workers` до 2
3. Закрийте інші програми
